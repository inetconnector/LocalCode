Berechtigungen

Standardberechtigungen
Dateien im Projekt lesen und bearbeiten; zusätzliche Zugriffe werden bestätigt.
Vollzugriff
Erlaubt Änderungen außerhalb des Projekts, Netzwerk und Befehle ohne zusätzliche Bestätigung. Nur in vertrauenswürdigen Projekten verwenden.

Shell für Agentenbefehle und das integrierte Terminal.
Sprache
Sprache der App-Oberfläche.
Untere Leiste

Standard-Terminalspeicherort

Geschwindigkeit

Import und Export

Einstellungen importieren

UI-Schrift

Coding-Agent-Engine

Bearbeitungs-Engine
Wählt die Engine für mehrdateilige Quellcodeänderungen. Aider eignet sich besonders für lokale Ollama-Modelle, Claude Code für Anthropic-Modelle und OpenCode für mehrere Provider einschließlich Ollama.
Aider aktivieren
Leitet echte Codeänderungen an die verwaltete Aider-Engine weiter. LocalCode behält Genehmigungen, Abbruch, Backups, MCP und Benutzeroberfläche unter Kontrolle.
Automatisch installieren
Installiert oder repariert die festgelegte Aider-Version beim Programmstart benutzerlokal. Globale Python-Pakete werden nicht verändert.
Aider-Version
Fest angeheftete und beim Start überprüfte Version.
Aider-Programmdatei
Optionaler vollständiger Pfad. Leer verwendet die verwaltete Installation oder eine gefundene Systeminstallation.
Hauptmodell
Leer verwendet das im Chat ausgewählte Ollama-Modell. LocalCode setzt automatisch das empfohlene Präfix ollama_chat/.
Architect/Editor-Modus
Trennt Planung und präzise Dateibearbeitung. Die Architekturantwort wird im nicht-interaktiven Lauf automatisch an das Editor-Modell übergeben.
Architect-Modell
Optional. Leer verwendet das Hauptmodell.
Editor-Modell
Optionales Modell, das ausschließlich Änderungen anwendet.
Edit-Format
Aider-Format für das Hauptmodell. diff ist für viele lokale Coding-Modelle robust.
Editor-Edit-Format
Format für das Editor-Modell im Architect/Editor-Modus.
Repository-Map-Token
Tokenbudget für die kompakte Symbol- und Referenzkarte des gesamten Projekts.
Aider-Verlaufslimit
Ab diesem weichen Tokenlimit fasst Aider den eigenen Bearbeitungsverlauf zusammen.
Automatisch linten
Führt nach Änderungen passende Linter aus und lässt Aider gefundene Fehler korrigieren.
Lint-Befehl
Optionaler projektspezifischer Befehl. Leer verwendet Aiders erkannte Standard-Linter.
Automatisch testen
Führt nach Änderungen Tests aus und speist Fehler wieder in die Reparaturschleife ein.
Testbefehl
Optionaler projektspezifischer Test- oder Buildbefehl.
Git in Aider verwenden
Nutzt Aiders Git-Sicherheitslogik nur, wenn das Projekt bereits ein Repository ist. Fehlendes Git blockiert Codeänderungen nicht.
Aider-Auto-Commits
Optional. Standardmäßig erstellt LocalCode keine automatischen Aider-Commits; Commits bleiben ein separater, genehmigter Schritt.
Claude Code aktivieren
Verwendet Claude Code im nicht-interaktiven Agentenmodus. Die Anmeldung erfolgt separat im sichtbaren Terminal.
Automatisch installieren
Installiert Claude Code beim Programmstart über den offiziellen benutzerlokalen Windows-Installer.
Release-Kanal
stable oder latest; optional kann eine konkrete von Claude Code unterstützte Version eingetragen werden.
Claude-Code-Programmdatei
Optionaler vollständiger Pfad. Leer verwendet die automatisch gefundene oder verwaltete Installation.
Claude-Modell
Zum Beispiel sonnet, opus oder eine konkrete Modellkennung.
Berechtigungsmodus
acceptEdits erlaubt Projektänderungen innerhalb der LocalCode-Genehmigungen; plan ist nur lesend.
Maximale Claude-Schritte
Begrenzt die Zahl der internen Claude-Code-Agentenschritte pro Aufruf.
OpenCode aktivieren
Verwendet OpenCode als providerunabhängige Agenten-Engine; lokale Ollama-Modelle und angemeldete Cloud-Provider werden unterstützt.
Automatisch installieren
Installiert Node.js bei Bedarf und OpenCode benutzerlokal, ohne globale Projekteinstellungen zu verändern.
OpenCode-Version
npm-Version oder latest.
OpenCode-Programmdatei
Optionaler vollständiger Pfad zur opencode-Programmdatei.
OpenCode-Modell
Leer nutzt das im Chat ausgewählte Ollama-Modell; alternativ provider/modell, zum Beispiel anthropic/claude-sonnet-4.
OpenCode-Agent
build für Änderungen, plan für lesende Analysen oder ein eigener konfigurierter Agent.
Änderungen automatisch anwenden
Übergibt --auto an OpenCode. LocalCode behält weiterhin Sandbox, Vorabgenehmigung, Backup und Abbruchkontrolle.

        

        
Modell und Laufzeit

        
Downloads für automatische Einrichtung erlauben
Erlaubt ausschließlich Downloads für aktivierte Installations- und Modelloptionen. Dieser Schalter ist unabhängig vom Netzwerkzugriff der Agenten und verhindert, dass eine deaktivierte Websuche den Programmstart blockiert.

        
Ollama-Adresse
Lokale Ollama-API. Standard: http://127.0.0.1:11434.

        
Ollama automatisch installieren
Lädt bei fehlender lokaler Installation den offiziellen Windows-Installer, prüft dessen Authenticode-Signatur und installiert Ollama für den aktuellen Benutzer.

        
Fehlende Modelle automatisch laden
Lädt das Standardmodell und explizit konfigurierte Aider-Modelle über die lokale Ollama-API, wenn sie fehlen.

        
Standardmodell für neue Installationen
Wird auf einem frischen Rechner automatisch geladen. Bereits installierte Modelle bleiben erhalten.

        
Kontextlänge
Kontextfenster des Modells. Bei 16 GB VRAM ist 32768 ein ausgewogener Startwert.

        
Kontext automatisch komprimieren
Verdichtet ältere Werkzeugergebnisse in einen überprüfbaren Arbeitszustand, bevor das Kontextfenster voll wird. Aufgabe, Entscheidungen, Dateien, Befehle, Fehler und offene Punkte bleiben erhalten.

        
Komprimierungsschwelle
Prozent des Kontextfensters, ab dem LocalCode ältere Nachrichten verdichtet. Empfohlen: 68 %.

        
Aktuelle Nachrichten behalten
Anzahl der jüngsten Nachrichten, die bei einer Komprimierung unverändert bleiben.

        
Maximale Agentenschritte
Obergrenze der Werkzeugschleife.

        
Befehls-Timeout
Maximale Laufzeit eines Befehls in Sekunden.

        
Zeitlimit pro Modellaufruf
Beendet einen festhängenden Ollama-Aufruf kontrolliert. Empfohlen: 240 Sekunden.

ComputeMesh Integration

        
ComputeMesh aktivieren
Verbindet LocalCode mit dem dezentralen ComputeMesh GPU-Cluster für 0% Plattformgebühr Provider Self-Compute.

        
Keys & Node automatisch erkennen
Liest Provider-Keys aus .computemesh oder Umgebungsvariablen und erkennt die lokale Workstation automatisch.

        
ComputeMesh API-Key
Persönlicher Provider-API-Key (z. B. cm_provider_...).

MCP-Plugins

        
Verwaltete MCP-Werkzeuge
LocalCode enthält Filesystem, PowerShell und Git direkt. Fetch, GitHub und Playwright werden über ihre offiziellen MCP-Server verbunden. Installationen, Anmeldung, Verbindungstest und Sitzungsreset sind hier vollständig steuerbar.

        
Erweiterte MCP-Konfiguration
JSON-Konfiguration für eigene stdio- oder Streamable-HTTP-Server. Die sechs verwalteten Standardserver werden beim Speichern ergänzt, falls sie fehlen.

Computernutzung und Sicherheit

        
Genehmigungsmodus
Regelt Bestätigungen für Dateiänderungen, Befehle und Netzwerkaktionen.

        
Sandbox-Modus

        
Werkzeuge automatisch finden
Sucht Programme über Projekt-Wrapper, PATH, Umgebungsvariablen und bekannte Installationspfade. Gefundene Programme werden mit absolutem Pfad ausgeführt.

        
Bei Werkzeugfehlern offizielle Hilfe recherchieren
Ergänzt fehlgeschlagene Werkzeugaufrufe um aktuelle Treffer aus der offiziellen Dokumentation, sofern Netzwerkzugriff aktiviert ist.

        
Feste Werkzeugpfade
Optionales JSON-Objekt, zum Beispiel {"adb":"C:\\Users\\frede\\AppData\\Local\\Android\\Sdk\\platform-tools\\adb.exe"}.

        
Werkzeugdiagnose
Prüft bekannte Entwicklungswerkzeuge einschließlich ADB, Java, Gradle, Git, Node, Python, Go, .NET und Docker.

        
Zusätzlich erlaubte Verzeichnisse
Ein Pfad pro Zeile.

        
Blockierte Befehlsmuster
Reguläre Ausdrücke, ein Muster pro Zeile.

        
Dauerhafte Freigaben
Befehlspräfixe und Werkzeugaktionen, die du über „Immer zulassen“ freigegeben hast. Regeln gelten nur für das angegebene Projekt oder global. Die restriktivste passende Regel gewinnt.

      


      
Hooks

        
Vor jeder Aufgabe
Nicht-interaktiver Befehl im Projektordner. Ein Fehler stoppt den Agentenlauf.

        
Nach jeder Aufgabe
Wird auch nach Abbruch oder Fehler ausgeführt; das Ergebnis erscheint im Chat.

        
Vor jedem Werkzeug
Nicht-interaktiver Befehl im Projektordner. Ein Fehler stoppt die Werkzeugausführung.

        
Nach jedem Werkzeug
Wird nach erfolgreichen oder fehlgeschlagenen Werkzeugaktionen ausgeführt und separat protokolliert.
