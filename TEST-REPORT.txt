LOCALCODE 6.0.0 - AIDER ENGINE TEST REPORT / PRUEFBERICHT
=====================================================================

Scope / Umfang
--------------
This release integrates Aider as LocalCode's managed production editing engine.
The review covered installation isolation, version pinning, Ollama model routing,
repository-map invocation, multi-file edit arguments, architect/editor mode,
Git behavior, conservative lint/test detection, persistent task histories,
approval handling, cancellation, process-tree termination, backups, guarded
undo, UI controls, localization, documentation, licensing and Windows builds.

Dieses Release integriert Aider als verwaltete produktive Bearbeitungs-Engine
von LocalCode. Geprueft wurden isolierte Installation, Versionsbindung,
Ollama-Modellweiterleitung, Repository-Map-Aufrufe, Argumente fuer
Mehrdatei-Aenderungen, Architect/Editor-Modus, Git-Verhalten, konservative
Lint-/Testerkennung, dauerhafte Aufgabenverlaeufe, Genehmigungen, Abbruch,
Prozessbaumbeendigung, Backups, geschuetztes Undo, UI, Uebersetzungen,
Dokumentation, Lizenzierung und Windows-Builds.

External verification boundary / Grenze externer Verifikation
---------------------------------------------------------------
The source test suite uses a controlled fake Aider executable to verify the
complete LocalCode/Aider process contract without changing a real repository.
An attempted live Aider download/install in this build container could not
complete because the environment could not resolve the external package hosts.
Therefore this report does not claim a successful live PyPI/GitHub installation
inside the build container.

On the target Windows computer LocalCode asks for approval, installs the pinned
version, executes aider --version, and marks Aider ready only after the expected
version is verified. The Settings page also provides explicit Install/repair and
Test repository map actions. A real local Ollama edit can only be validated on
the target computer because it depends on that computer's Ollama service,
models, network access and project contents.

Die Quelltests verwenden eine kontrollierte Aider-Testprogrammdatei, um den
vollstaendigen LocalCode/Aider-Prozessvertrag zu pruefen, ohne ein echtes
Repository zu veraendern. Ein echter Aider-Download in diesem Build-Container
konnte wegen fehlender DNS-Aufloesung zu den externen Paketservern nicht
abgeschlossen werden. Deshalb wird hier keine erfolgreiche Live-Installation
im Build-Container behauptet.

Auf dem Windows-Zielrechner fragt LocalCode nach Genehmigung, installiert die
festgelegte Version, fuehrt aider --version aus und meldet Aider erst nach
korrekter Versionspruefung als bereit. In den Einstellungen stehen zusaetzlich
Installieren/Reparieren und Repository Map testen zur Verfuegung. Ein echter
lokaler Ollama-Bearbeitungslauf kann nur auf dem Zielrechner geprueft werden,
weil er von dessen Ollama-Dienst, Modellen, Netzwerk und Projektdateien abhaengt.
