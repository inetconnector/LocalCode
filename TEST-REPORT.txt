LOCALCODE 6.1.0 - FINAL TEST REPORT / ABSCHLUSS-PRUEFBERICHT
=====================================================================

Scope / Umfang
--------------
This release fixes the native Windows failures reported for cancellation,
legacy-data migration, MCP process cleanup, temporary project roots, project
catalog isolation and tool discovery. It also adds automatic setup for Go,
Ollama, required Ollama models and Aider, plus sandbox and network hardening.

Dieses Release behebt die gemeldeten nativen Windows-Fehler bei Abbruch,
Migration alter Nutzerdaten, MCP-Prozessfreigabe, temporaeren Projektwurzeln,
Projektkatalog-Isolation und Werkzeugerkennung. Zusaetzlich wurden die
automatische Einrichtung von Go, Ollama, benoetigten Ollama-Modellen und Aider
sowie Sandbox- und Netzwerkhaertung umgesetzt.

-----------------------------------------------------
PASS  Aider cancellation terminates the complete Windows process tree and
      waits for Cmd.Wait instead of leaving child handles open
PASS  legacy product-data migration honors LOCALCODE_*_HOME and XDG test paths
      on Windows instead of reading the real user profile
PASS  persistent MCP stdio sessions wait for actual process termination before
      TempDir cleanup
PASS  legitimate temporary Windows project roots are no longer replaced by

PASS  project catalog, aliases and thread-context tests are isolated from the
      real project folder
PASS  the ADB test uses a real compiled Windows helper executable
PASS  missing-tool tests isolate PATH, Android SDK variables and profile paths

Automatic setup / Automatische Einrichtung
-------------------------------------------
PASS  START.bat rebuilds when LocalCode.exe is missing or source/build inputs
      are newer
PASS  BUILD.bat accepts a supported Go 1.25+ toolchain or installs the current
      stable Windows-amd64 Go archive from go.dev and verifies its official
      SHA-256 value
PASS  startup detects and starts an existing Ollama installation
PASS  missing Windows Ollama is downloaded only from ollama.com, requires a
      valid Authenticode signature and is installed unattended for the user
PASS  missing configured Ollama models are pulled automatically
PASS  fresh installations use qwen2.5-coder:14b unless another default is set
PASS  explicitly configured Aider main/architect/editor models are included
PASS  Aider 0.86.2 is verified and automatically installed or repaired through
      pinned, SHA-256-verified portable uv and an isolated Python 3.12 tool env
PASS  existing valid installations and models are reused
PASS  German and English settings expose all automatic-setup controls

Security and reliability / Sicherheit und Zuverlaessigkeit
------------------------------------------------------------
PASS  project sandbox resolves existing symlinks and NTFS junctions at the
      nearest existing ancestor, including non-existing write destinations
PASS  web fetch validates and dials the same resolved public IP, preventing a
      second DNS lookup from rebinding to a private/local destination
PASS  redirects and supported web-search providers use the same public-IP rule
PASS  dependency downloads use fixed official origins and integrity/signature
      checks where available
PASS  Aider and MCP subprocesses are reaped deterministically
PASS  no executables built with the container's obsolete Go 1.23.2 are shipped

External verification boundary / Externe Verifikationsgrenze
--------------------------------------------------------------
The verification container runs Linux and cannot execute the resulting Windows
programs or batch files natively. Windows test binaries and both applications
were successfully cross-compiled, but the exact post-fix command
`go test ./...` must still be run once on the target Windows system. The target
reported Go 1.26.5, so START.bat will use that supported installation.

Live Ollama, model and Aider downloads were not executed in this container.
Their internal request, parsing, installation orchestration and model-refresh
contracts are covered with controlled tests, but final success also depends on
the target computer's Windows configuration, network, available disk space and
Ollama service startup.

Der Pruefcontainer laeuft unter Linux und kann die erzeugten Windows-Programme
und Batchdateien nicht nativ starten. Windows-Testprogramm sowie GUI- und
Diagnoseprogramm wurden erfolgreich cross-kompiliert; der konkrete korrigierte
Befehl `go test ./...` muss dennoch einmal auf dem Windows-Zielsystem laufen.
Dort wurde Go 1.26.5 gemeldet, das START.bat direkt verwenden wird.

Echte Ollama-, Modell- und Aider-Downloads wurden im Container nicht ausgefuehrt.
Anfrage-, Auswertungs-, Installations- und Modellaktualisierungsablaeufe sind
mit kontrollierten Tests abgedeckt; der reale Erfolg haengt zusaetzlich von
Windows, Netzwerk, Speicherplatz und dem Start des Ollama-Dienstes ab.
